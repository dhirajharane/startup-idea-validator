## Overview

StartupInspector is a Next.js application for entrepreneurs who want a fast,
structured first pass on a startup concept. Authenticated users submit an idea
from the dashboard, spend one analysis credit, and receive a report generated by
LangChain chains backed by Groq. Reports can be saved and revisited from the
dashboard and report history.

The application can optionally enrich the analysis with external search results
from SerpAPI. If no SerpAPI key is configured, competitor and market-trend
sections use the application's fallback behavior instead.

**Live demo:** [startup-idea-validator-omega.vercel.app](http://startup-idea-validator-omega.vercel.app/)

## Features

- **Structured AI analysis** with:
  - Overall summary and conclusion
  - 0–100 validation score with category breakdown
  - SWOT analysis
  - Monetization strategies
  - Actionable insights
  - Pitch-deck outline
  - Competitor landscape
  - Market trends and trend summary
  - Warnings when applicable
- **Account creation and sign-in** with email/password credentials.
- **Dashboard and history** with recent reports, saved reports, credits, and
  download counters.
- **Saved reports** for returning to promising ideas later.
- **Credit-based usage**: new users receive 15 credits; each generated report
  consumes one credit.
- **Responsive dark UI** with animated interactions built using Tailwind CSS,
  Radix primitives, Lucide icons, and Motion.

> **Current product behavior:** the report view includes a download action, but it
> currently displays a premium notice instead of downloading a PDF. The backend
> PDF-generation route remains present for future product use.

## How it works

1. A visitor opens the landing page and signs up or signs in.
2. The authenticated dashboard accepts a startup description of up to 1,000
   characters.
3. The server validates the request, checks the user's remaining credits, and
   runs the report-generation chains.
4. The resulting report is validated against a Zod schema and stored in MongoDB
   in a transaction with the user's history and credit decrement.
5. The report is displayed with charts and dedicated sections for findings,
   SWOT, monetization, insights, pitch planning, competition, and market trends.
6. Users can save the report and access reports through the dashboard history.

## Getting started

### Prerequisites

- Node.js 18.17 or newer
- A MongoDB database and connection string
- A Groq API key
- A SerpAPI key if you want external competitor and market-trend search

### Installation

```bash
git clone https://github.com/dhirajharane/startup-idea-validator.git
cd startup-idea-validator
npm install
```

### Environment variables

Create a `.env.local` file in the project root:

```env
MONGODB_URI=mongodb+srv://<username>:<password>@<cluster>/<database>
AUTH_SECRET=replace-with-a-long-random-secret
GROQ_API_KEY=your-groq-api-key

# Optional: defaults to openai/gpt-oss-20b when omitted
GROQ_MODEL=openai/gpt-oss-20b

# Optional: enables external competitor and market-trend search
SERP_API_KEY=your-serpapi-key
```

Keep `.env.local` private and never commit API keys or database credentials.

### Run locally

Start the development server:

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

For a production build:

```bash
npm run build
npm run start
```

The repository also defines a lint script:

```bash
npm run lint
```

## API routes

The main server routes include:

- `POST /api/register` — create a user account.
- `POST /api/report` — validate and generate a report.
- `GET /api/user-reports` — retrieve the authenticated user's report history.
- `GET /api/saved-reports` / `POST /api/saved-reports` — read and save reports.
- `POST /api/download-report` — authenticated PDF-generation endpoint.
- `GET|POST /api/auth/[...nextauth]` — NextAuth handlers.

Report generation requires a valid user, an idea of at least 10 characters, and
at least one remaining credit.

## Security and configuration notes

- Dashboard routes are protected by middleware and server-side session checks.
- Passwords are hashed with `bcryptjs`; passwords must be at least eight
  characters long.
- MongoDB connections are cached for reuse during development and server
  execution.
- Groq model access is server-side and requires `GROQ_API_KEY`.
- External search is optional; missing SerpAPI configuration does not prevent
  report generation.
